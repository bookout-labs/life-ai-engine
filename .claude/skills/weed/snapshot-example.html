save.ts, piece by piece

313 lines. What each piece does, and whether a platform already does it better.

Setuplines 1–12

Loads Node's built-in tools and finds the repo folder.

KeepPlumbing every script needs.
2
Save locklines 13–16, 181–189, 304–313

Makes a lock folder so two saves can't run at the same time. Treats a lock older than 15 minutes as abandoned.

T3 CodeWorktree threads give every session its own checkout, so saves can't collide.
3
Hand-off to main's gatelines 18–51

Downloads main's copy of save.ts, review.ts and proof.ts into a temp folder and re-runs itself from there. That way a change can't approve itself by editing the rules that judge it.

GitHubThis only exists because review runs on your machine. A required check on GitHub runs main's rules by design. Move review there (piece 15) and this disappears.
4
Read argumentslines 53–66, 84

Reads the work ID, message, issue number and proof note from the command.

KeepAlready uses Node's built-in argument parser.
5
Expand folders into fileslines 67–83

If you name a folder, lists every changed file inside it, including renamed ones.

gitgit add docs/ already does this. After staging, git diff --cached --name-only gives the real file list.
6
Check the inputslines 86–108

Rejects a bad work ID, missing message or bad issue number. Asks proof.ts whether these files need an issue or proof, and confirms the issue is open.

KeepThese are Life AI's own rules. CI enforces the same rules; this just fails fast before anything is pushed.
7
GitHub App loginlines 110–135

Makes a short-lived token for the bookout-life-ai-agents App, so saves happen as the App instead of as you.

KeepUses GitHub's own gh token generate. Nothing hand-built.
8
Must start on mainlines 192–194

Refuses to save unless you're on the main branch.

T3 CodeWith worktrees, each thread already has its own branch.
9
Rebuild INDEX.mdlines 196–197

Regenerates the knowledge index and adds it to the save if it changed.

GitHub ActionsHave CI generate or verify it. Doing it here caused the overlap bug, where one session shipped another session's index.
10
Run the full check locallylines 199–203

Runs npm run check (types, lint, tests, rules) before saving.

GitHub + harnessCI's required check runs the same thing and can't be skipped. The edit-time lint hook already gives fast feedback while working.
11
Nothing-to-save checklines 205–209

Stops quietly if the named files have no changes.

KeepOne git call.
12
Agent and session labelslines 211–220

Works out which agent is saving and its session ID, and stamps them on the commit.

Your callClaude Code and Codex add their own co-author lines, and T3 links each PR to its thread. The one thing still used is the agent name, which picks the reviewer. That goes away if review moves to GitHub.
13
Dry runlines 222–226

With --dry-run, prints what it would do and stops.

Your callSmall, rarely used. git status shows the same thing.
14
Branch and commitlines 228–237

Checks the App key exists, creates a save/… branch, stages the files and commits with the work ID.

KeepThis is the actual save.
15
Cross-family reviewlines 239–262 (plus review.ts, 138 lines)

Reads the board issue and counts blocked rounds (stops at 3). Has the other company's agent review the diff locally and posts blocked rounds on the issue. Writes the "Review: pass" receipt into the PR.

GitHubCodex reviews PRs automatically on your ChatGPT plan. Claude's GitHub Action runs on your Claude subscription. Either one can be a required check that the PR can't tamper with, so the hand-off, receipt and receipt-checking go away. The 3-round cap would move into that workflow. Needs a test first: whether Codex's review can actually block a merge.
16
Push, open PR, turn on auto-mergelines 264–270

Pushes the branch, opens the PR as the App, and tells GitHub to merge it when checks pass, but only at this exact commit.

KeepAlready hands the merge to GitHub. save.ts could end right here.
17
Wait for mergelines 137–160, 271–274

Sits and watches the checks, waits for GitHub to merge, then pulls main.

GitHub + T3 CodeAuto-merge already does the merging. T3's PR watch (or GitHub's notifications) reports the outcome, so the agent doesn't have to sit there.
18
Production proof and evidencelines 162–179, 275–284

Waits for ship.yml to deploy and smoke-test, then posts the proof on the board issue.

GitHub Actions + Projectsship.yml already runs the deploy and tests. It can post the evidence and close the issue itself, and the board's built-in "closed → Done" setting moves the card.
19
Failure recoverylines 285–301

If anything fails, undoes the commit, returns to main, deletes the branch and closes the PR so it can't merge later.

T3 Code + GitHubIn a worktree, a failed save just leaves that thread's files as they were. If save.ts ends at auto-merge, a PR that fails checks stays unmerged on its own.
