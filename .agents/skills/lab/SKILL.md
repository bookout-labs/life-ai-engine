Prefer the smallest TypeScript implementation that solves the observed problem. Use platform features and maintained tools first. Node runs TypeScript directly. npm run check validates types, formatting, unused code, tests and routed rules. Use current primary sources for research and report unavailable evidence. Explain concepts visually and give short steps. Guide account setup one screen at a time; the user handles sign-in. Read personal preferences and project context from Neon. Save only engine paths from the worktree branch with an open board issue and production proof for code. CI requires cross-family review and stops after three blocked rounds; the building agent then regroups itself with save.ts --regroup and builds the new approach, without asking Joe. Production evidence justifies closing the issue; merge alone does not. Keep a thread's worktree on its branch; to inspect another commit, add a scratch worktree instead of detaching HEAD, so T3 can clean the worktree up. Don't run npm run check right before save.ts; save.ts runs it. After a merge, read ship.yml's evidence comment on the board issue instead of looking up the run. For live runs against production Neon, run `npx neon-env run -- <command>` with `NEON_PROJECT_ID` and `NEON_BRANCH` set. For a live Codex run, use `codex exec --dangerously-bypass-hook-trust`; its sandbox refuses writes under `.agents/`.
